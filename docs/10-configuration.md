## 10.2 Installation

```bash
# 1. Dependencies
composer install
npm install

# 2. Environment
cp .env.example .env          # Windows: copy .env.example .env
php artisan key:generate

# 3. Database (see .env for the credentials)
php artisan migrate --seed

# 4. Front end
npm run build

# 5. Serve
php artisan serve
```

The application is then available at <http://127.0.0.1:8000>.

> `composer setup` performs steps 1, 3 and 4 automatically (and copies `.env` and
> generates the key).

### Installing with phpMyAdmin / shared hosting

Import `database/quiz_system.sql`, which contains the same schema **and** the
same demo data as the seeder. Afterwards run `php artisan migrate` once so
Laravel records the schema baseline. The domain migrations are idempotent, so
they detect the existing tables and do nothing.

### SQLite instead of MySQL

```dotenv
DB_CONNECTION=sqlite
DB_DATABASE=/absolute/path/to/database/database.sqlite
```

The `database/database.sqlite` file in the repository is a leftover from an
earlier SQLite-based version; it is not used by the default configuration.

## 10.4 Artisan commands

### Provided by the project

| Command | Purpose |
|---|---|
| `php artisan certificate:edge-image` | Regenerates `public/images/cert-edge.png` (needs the GD extension) |

### Used in the normal workflow

| Command | Purpose |
|---|---|
| `php artisan key:generate` | Creates `APP_KEY` |
| `php artisan migrate` | Applies the migrations |
| `php artisan migrate --seed` | Applies the migrations **and** loads the demo data |
| `php artisan migrate:fresh --seed` | Drops everything and rebuilds it with the demo data |
| `php artisan db:seed` | Loads the demo data only |
| `php artisan route:list` | Lists every route |
| `php artisan config:clear` | Clears the configuration cache |
| `php artisan cache:clear` | Clears the application cache |
| `php artisan view:clear` | Clears the compiled Blade views |
| `php artisan storage:link` | Creates the `public/storage` symlink |

### Used during development

| Command | Purpose |
|---|---|
| `php artisan serve` | The development server |
| `php artisan queue:listen --tries=1` | A queue worker (only needed if `QUEUE_CONNECTION` is changed) |
| `php artisan tinker` | An interactive PHP shell |
| `php artisan pail` | Tails the log file |
| `php artisan test` | Runs the test suite |

`composer dev` runs `serve`, `queue:listen` and `npm run dev` side by side.

## 10.7 Deployment checklist

```bash
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

| Item | Requirement |
|---|---|
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_KEY` | Set, and the same value on every server |
| `APP_URL` | The real public URL — the verification and reset links are built from it |
| `MAIL_MAILER` | `smtp` with real credentials, otherwise no e-mail is ever sent |
| `storage/` and `bootstrap/cache/` | Writable by the web server |
| `public/build/` | Must exist — it is git-ignored and has to be built on the server |
| `public/fonts/`, `public/css/`, `public/images/` | Must be deployed — the certificate depends on them |
| Document root | Must point at `public/` |

The health endpoint `GET /up` returns 200 once the application boots and is
useful as a readiness probe.

## 10.8 Scheduled work

There is **no** scheduler: `routes/console.php` contains only the stock
`inspire` command and `bootstrap/app.php` does not schedule anything. The
queue connection is `sync`, so no worker is required for the current feature
set.

## 10.9 Logging

| What | Where |
|---|---|
| Application log | `storage/logs/laravel.log` (single channel) |
| E-mails (with `MAIL_MAILER=log`) | The same file |
| Verification mail failures | Reported with `report($e)` → the log |
| Queue failures | `storage/logs` / the `failed_jobs` table |

## 10.10 Storage layout

| Path | Contents |
|---|---|
| `storage/app/` | Application files. `storage/app/fonts` holds the Dompdf font cache and is created on demand |
| `storage/framework/cache` | Cached data |
| `storage/framework/sessions` | Session files (the `file` driver) |
| `storage/framework/views` | Compiled Blade templates |
| `storage/logs` | The log file |

None of these are tracked by git.
